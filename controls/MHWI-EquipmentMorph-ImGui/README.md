# Dear ImGui 游戏内面板：第八阶段界面完善候选

提供独立、可选的 `MHWEquipmentMorphImGui.dll`。通过公开 API 接入装备选择和形态键控制，使用统一的深色、蓝色交互和状态提示。核心插件继续独立提供形态键支持，不需要面板或旧控制桥接。

2026-10-20 用户确认第七阶段调宽及[预设导入／导出](../../docs/PRESETS.md)测试通过。第八阶段分开呈现浏览预设、当前配置和操作结果，明确保存对象，改善窄窗口与长名称显示，并统一控件间距、颜色和权重显示。核心与预设格式保持，复选框及显式零权重语义保留；新候选待用户实机测试。

## 使用

1. 在游戏获得焦点时按 **Ctrl＋Shift＋M** 呼出／隐藏。
2. 下拉选择当前已绑定、具有形态键数据的装备部位。列表来自核心 API，不列出未穿戴／尚未绑定的模型，也不替玩家换装。
3. 每行四列为 **形态键 | 目标权重 | 精确输入 | 实际权重**。拖动滑块即时提交；输入框按回车提交。仅查看和选择不会接管权重。
4. 修改一个键即接管该键；名称前的勾选表示本面板是否持有贡献。取消勾选仅释放这一键；“释放全部控制”释放本面板全部贡献。
5. 快捷键隐藏、失去焦点、最小化会保留贡献；点击面板 **×** 释放本面板控制并隐藏。释放会显露其他来源或恢复基准，实际形变仍沿核心既有平滑流程恢复。

精确输入保留 float32 的 9 位有效数字；滑块与实际权重统一显示 3 位小数，不据此量化提交或保存值。最后一列读取核心的 **已应用权重**，因此平滑时可能与编辑值暂时不同；悬停仍可查看 9 位有效数字的请求／实际值及是否有其他来源优先。无效／越界输入和互斥冲突会显示错误，并保留此前已接受的贡献。

预设区分为“浏览预设”和“当前配置”：应用所选才改变当前权重；保存当前始终更新当前配置，即使正在浏览另一项也不会覆盖该浏览项，保存后保留浏览选择。当前配置使用文字和颜色提示未保存状态。成功、未完成和处理中结果使用统一样式，长结果可展开查看，长名称悬停显示完整内容。管理列表标记关联的当前配置；按钮在空间不足时换行。界面设置跨重启保存暂未加入，现有会话内调宽保持。

切换下拉选择会保留其他已控制键和部位。换装后的新目标不继承旧目标权重；旧目标排队中的编辑也不会重放到同名新模型。来源租期过期时丢弃旧命令，需重新调节。

## 安装与回滚

需要 Windows x64、DX12 模式和 Stracker's Loader。正常退出游戏后，将配套构建的 `MHWEquipmentMorphConfiguredPrototype.dll` 与 `MHWEquipmentMorphImGui.dll` 放入 `nativePC/plugins/`，保留 `runtime.ini` 与装备资产。旧核心搭配新面板仍可调节权重，但没有身份扩展时不能使用预设。不需要外部 EXE、Tauri、WebView2 或控制桥接。

回滚：正常退出游戏后恢复核心和 GUI 的配套备份，预设文件可保留。仅停用界面时可移除 GUI DLL；核心仍可由其他插件通过公开 API 使用。许可证随源码／候选文件保留，不重新分发系统字体。

## 构建与非界面验证

在仓库根目录运行：

```powershell
./tools/build_mhwi_equipmentmorph_imgui.ps1
```

默认输出 `.build/current-validation/imgui/`，可用 `-OutputDirectory` 指定目录。使用现有 MSVC／Windows SDK，不重建／安装核心。脚本编译 DLL、历史软件窗口程序，以及无窗口的 `ImGuiControlTests.exe` 和 `ImGuiPresetTests.exe`，**只执行控制与预设的控制台测试**。33 项控制回归覆盖接口校验、命令合并、贡献隔离、实际应用值、冲突拒绝、隐藏续租、目标替换、释放取消排队编辑、租期过期、并发发布、float32 精度、快速实际权重读回、隐藏降频及换装发现。预设回归另覆盖筛选、管理、永久删除、部分失败与管理栏的屏幕边界计算；呈现和操作手感仍由用户验证。

用户已确认第二阶段修复版的界面与输入测试通过。此后界面交互、窗口呈现及实机测试统一交由用户执行，助手不启动或自动操作测试窗口。2026-10-20 用户确认第三阶段的调节、多部位控制、显隐／释放及换装后的列表更新正常，上述功能实机验收通过。该结果对应源码提交 `d30799d` 生成并部署的 DLL（SHA-256：`a35bdcde36690b591811ef7636725a11a3f583c93fa56ed5fa6ce78e2118b469`），后续重新构建的产物需另行验证。

历史工具 `EquipmentMorphImGuiFixture.exe` 和 `tools/test_mhwi_equipmentmorph_imgui.ps1` 仍保留用于手动复现 DX12 先／后加载、队列干扰、Reset 与缩放。它们会创建窗口，不能作为助手默认检查。测试机未安装 DX12 Debug Layer，历史日志中的 `d3d12_errors=0` 不代表调试层验证通过。

## 运行方式与日志

- 可选 DLL 使用已验证的窗口、输入及 DX12 路径。支持插件加载时交换链已存在；优先使用创建时队列，或从后台缓冲最终转换与命令提交识别渲染队列。特殊跨队列呈现／交换链包装兼容性仍以实机为准。
- 权重 API 只由普通后台线程调用。渲染与输入线程交换不可变快照和合并后的编辑命令，不直接枚举目标或提交权重。装备与键元数据约每 250ms 扫描；显示时约每 16ms 合并处理输入并读回已应用权重，快速读回不重复枚举装备与键。隐藏时停止快速读回，继续低频扫描和续租。会话复用现有控制会话逻辑，优先级 220、租期 2000ms。
- 隐藏时跳过 ImGui 帧与 GPU 提交。GUI 停用会请求释放本面板来源。其他来源的贡献保持独立。
- 快捷键只在游戏拥有焦点时注册；失焦解除注册。键盘／鼠标捕获沿用第二阶段已通过用户测试的路径；手柄和 GetRawInputBuffer 尚未接入。
- 日志：`nativePC/plugins/MHWEquipmentMorph/logs/imgui-<PID>.ndjson`。本阶段标记为 `stage=8`，`preset_count`、`usable_presets`、`recycled_presets` 分别记录总数、可用数与回收区数量。正常为 `boot=1`、`error=none`、`window_ready=true`、`queue_ready=true`，快捷键注册为 `hotkey_registered=true`、`hotkey_error=0`。
- 接口字段：`api_connected`、`control_ready`、`targets`、`source`、`control_result`、`snapshot_result`。只查看时 `source=0`；接管后为本面板来源，释放后回到 0。错误码沿用公共 API。
- 依赖为固定 Dear ImGui v1.93.0，来源及逐文件摘要见 [UPSTREAM.json](../../research/imgui-v1.93.0/UPSTREAM.json)。系统字体使用 `msyh.ttc`，不重新分发字体。

2026-10-20 新增快速响应候选，尚待用户实机测试：配套核心将临界阻尼参数由 `omega=8` 调整为 `80`，理想阶跃约 59ms 达到 95%、83ms 达到 99%；保留速度连续性、边界约束、原有约 16ms 网格采样及 GPU 资源协议。这会影响核心接收的所有来源权重，并非仅面板滑块。面板显示仍读取核心确认值，不预测或替换实际值。
