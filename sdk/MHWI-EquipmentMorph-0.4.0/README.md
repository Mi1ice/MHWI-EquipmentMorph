# MHWI-EquipmentMorph · SDK 0.4.0

Windows x64，C++20；公共C ABI仍为65536，既有宿主兼容。只供同一MHW进程中的原生插件使用；运行时由Stracker's Loader加载，无SharpPluginLoader依赖。自动表情在独立项目实现。

在普通工作线程或UI事件中创建并保留客户端，调用`mhwi_example::ConnectLoaded`连接已经加载的宿主。未就绪可稍后重试，不另行LoadLibrary独立核心。不在DllMain连接或控制。调用者负责每500ms续租并停止失效来源；客户端实例自身不是线程安全对象。

`mhwi::KeyClient::Set`接受部位、模型ID、形态键名称及连续权重的列表，支持跨部位批次；只接管列出的键，其它已接管键保持。`ReleaseKey`释放一个键，`Release`释放本来源全部贡献，析构也释放。模型与键名由你的导出包/运行时`Keys()`提供，不沿用旧索引。无效/重复/互斥冲突请求不会替换原贡献。默认来源优先级200、租期2000ms，可在构造时指定，公共API分别限制0–255及100–60000ms。

`morphpartclient::Client`保留已观察的完整部位控制机制；`ApplyFullParts`按调用者提供的模型和键名解析，每个选中部位的其它键显式置零。完整部位接管适用于调用者独占这个部位；希望和其它来源逐键协作时使用KeyClient。两种方式不能把“未列出键”混同为相同语义。

公开接口`submit`替换本来源的完整贡献集；包装器缓存明确接管的键/部位以满足该约定。显式0仍接管并覆盖低优先级，释放才交回控制。每键最高优先级来源胜出，同优先级较早的来源胜出；窗口来源优先级220。换装新句柄不重放旧权重，仍有效部位的贡献保留；租期丢失时清除缓存，后续只有明确的新Set请求才能重新控制。

`Read`分别给出请求与已发布状态。成功提交表示请求接受，不等于GPU完成；平滑过程和独立部位会有发布延迟。C API的结果、能力与数量限制见`mhw_morph_api.h`。客户端不加载模型/形态键数据、不上传GPU、不发现游戏对象。

示例使用合成数据，不绑定实际MOD。SDK14项通用检查纳入源码统一验证；0.5.0实机验收范围见[验证说明](../../docs/VALIDATION.md)。
