# 0.5.1-dev5：每周期校验装备身份

历史阶段说明：本页保留对应开发版本的设计、检查数量与当时测试步骤。相关修复已纳入main的dev12基线，本轮用户功能验证与性能优化均已结束；当前状态见[项目状态](PROJECT_STATUS.md)及[dev12结论](DEV12_BASELINE.md)。下文的候选“待复测”不代表当前新增任务。

原LaunchStarting对每个装备、每个原生工作线程都重复执行主玩家和完整模型/源缓冲身份检查。dev5在每周期worker 0、以及尚未启动的新绑定执行完整检查。只有worker 0可以发布新输入，后续worker继续由Launch验证同一引擎、渲染器、Fence、线程、周期计数、模式、工作线程数、事件和严格启动顺序。

没有增加跨周期身份缓存。新适配器不能继承旧代际的检查结果；周期中途发现的新绑定仍需校验，并等待worker 0启动。ModelChanging和玩家移除回调继续立即使绑定失效。非零Input在替换私有缓冲前仍执行完整身份校验；稳定零值继续使用dev4的原输入轻量路径。未经过生命周期回调的静默身份变化，非零输入会在替换前拒绝，下一周期worker 0也会重新检查。退役、Wait/Join/Signal及上传/绘制Fence证明保持不变。

新增22项直接调用生产LaunchStarting的合成回归，覆盖首线程、后续线程、下一周期、新代际、中途绑定、模型/玩家变更、非零替换、启动顺序、事件、周期计数、模式、工作线程数和渲染器关联。新读取断言先在dev4上失败，修改后原生共382项通过。

同一自有内存夹具中，每周期一个身体目标：首线程读取保持57次，后续线程由57次降到9次。三个线程的整周期合成CPU耗时约50.96→22.88微秒，八个线程约138.68→36.40微秒。夹具包括LaunchStarting和模拟Wait/Join/Signal状态推进，无真实Hook、游戏或GPU调用；不是实机帧率测量。单线程场景无重复检查可省。

dev4已由用户在同一场景测试通过：零值约200 FPS，比dev3高50 FPS；非零约160 FPS。这是用户报告的近似平均帧率，没有采集逐帧时间，不能归因全部剩余开销。dev5仍需用相同场景、视角、装备和控制方式与dev4比较。

正常退出游戏和控制窗口后安装MHWI-EquipmentMorph-0.5.1-dev5-source.zip，保留已有公共runtime.ini。依次检查全零、持续非零、调整后归零；再保持控制不释放，进行001→其它套装→001，确认自动重绑、新目标零值及重新调节正常。空闲平滑轮询仍待后续处理；非零逐网格校验本轮未改。
