## 复测与物理状态补偿

用户于11:46确认交接候选仍可复现。该段日志松键等待已完成、左键队列未持续积压，窗口消息处理的累计最长耗时为16ms。11:52再次由用户复现，并用外部只读采样记录了物理左键按下／松开、前台窗口、光标下窗口、捕获归属及系统移动／菜单模式。返回点击时前台和光标下方均为游戏，没有其他窗口捕获、没有系统移动或菜单模式；点击未体现为面板拖动／松键计数，绘制持续。这排除了本次采样中的捕获抢占和已记录窗口回调长时间阻塞，提示鼠标消息入口不可靠；仍不能确认具体是哪个输入组件或消息分发环节导致。

本轮保留正常窗口事件，并在每个可见输入帧校验物理鼠标位置和五个按钮：

- 使用原始按键查询的当前按下位，绕开本面板对游戏轮询的屏蔽，并按系统左右键交换设置映射到逻辑按钮；位置也独立采样，避免缺失移动／离开通知后悬停位置不再更新。[GetAsyncKeyState](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getasynckeystate)。
- 已排队的窗口按钮事件先正常消费，保留两帧之间完成的短点击；没有该按钮的排队事件而界面状态与物理状态不同，才补充按下或松开。
- 发生物理状态补偿后，迟到且早于该次补偿的窗口按钮消息不再重放；处理等待界面锁期间发生的补偿竞争，并容忍系统32位消息时间回绕。[GetMessageTime](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmessagetime)。
- 鼠标范围及捕获清理仍由窗口线程执行。物理采样只发出合并任务；缺失松键时补全交接，快速重按仍受拖动序号保护。正常松键也补充一次合并清理，避免后端遗漏按钮状态导致捕获残留。

这补偿输入入口失配，不将前一版交接修正标为解决根因。当前物理补偿候选仍需用户实机复测。

## 风扇升速、闪烁与光标显隐返回值

2026-10-22 用户确认物理状态补偿候选解决面板卡顿，但录像中返回点击后风扇升速，约10.54秒面板短暂消失一个录制帧，随后光标消失。该次日志呈现及绘制持续，相关采样的呈现速率约229至234帧/秒；无交换链重建、GPU忙帧跳过或窗口回调长时间阻塞记录。原生鼠标消息计数在一段时间内停止增长，物理补偿仍使面板可操作。缺少同步CPU/GPU和调用栈采样，不能仅凭录像判定风扇所属或唯一根因。

审查发现确定的返回值缺陷：面板接管时，`ShowCursor(TRUE)`和`ShowCursor(FALSE)`均被固定返回0。Windows规定返回值是新光标显示计数，负数代表隐藏。若宿主使用`while (ShowCursor(FALSE) >= 0)`，旧返回值使循环不能结束，可能令宿主线程忙等，且窗口过程阶段计时不会涵盖位于消息分发之外的循环。此为静态可复现缺陷；尚未证明本次实机调用栈正在执行该循环。[ShowCursor接口约定](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showcursor)。

修正候选在面板接管期间对显示请求返回0、隐藏请求返回-1，不改变本面板持有的真实光标计数；隐藏面板及其他未接管路径继续调用原函数。控制台以有上限的宿主循环模型验证旧返回值不能终止、新返回值使显示及隐藏均在一次调用后终止，并覆盖反复切换和非标准非零BOOL。不会执行系统光标操作或注入输入。

约两秒一次的状态日志另增加`cursor_show_calls`、`cursor_hide_calls`和`cursor_suppressions`，分别统计非面板内部的显示、隐藏请求及被面板接管的请求。修正的实机效果、风扇和光标恢复仍待用户验证；只读采样工具已准备，可同步线程CPU、显卡功耗／风扇、窗口捕获／光标及逐帧呈现数据。

## 松键顺序

原流程在窗口线程收到 `WM_LBUTTONUP` 时先解除鼠标范围限制，之后才调用 ImGui 后端入队松键事件。ImGui 在后续 `NewFrame` 才消费事件，且输入事件可能逐帧处理。这允许鼠标在界面仍认为正在拖动时跨出游戏。

修正流程：

1. 收到左键按下或双击时，为本次拖动建立序号并限制鼠标范围。
2. 收到左键松开后，先正常交给 ImGui 后端，标记等待交接，暂不解除范围限制。
3. 渲染线程在 `NewFrame` 后确认左键已松开，且没有待处理的左键事件，再发出带序号的确认。
4. 窗口线程核对序号及当前物理左键状态，才解除范围限制。旧确认、快速重按、重复松键和发送失败均不会提前释放新的拖动。

这不是固定延时；正常情况下只等待必要的输入帧。解除限制的确认分支不获取界面锁，也不在渲染线程调用 `ClipCursor`。失焦、隐藏、最小化或意外捕获丢失会立即取消交接并解除临时限制，避免将鼠标困在失焦窗口中。

## 消息归属

面板接管输入时，`WM_MOUSELEAVE`、`WM_NCMOUSELEAVE`、`WM_CAPTURECHANGED` 先交给面板处理，不再传给没有收到相应按键序列的游戏处理函数。真实的焦点、激活和窗口尺寸通知继续传递。

`ReleaseCapture` 自身也会触发捕获变更通知，不能将它一律视为新的意外捕获丢失。正常松键交接期间保留等待；其他窗口取得捕获时立即取消并清除面板按钮状态。[Windows 捕获变更说明](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-capturechanged)、[ReleaseCapture](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-releasecapture)。

## 日志

原有约两秒一次的状态日志新增：

- `drag_releases`、`drag_release_pending`：完成交接次数及是否仍等待。
- `mouse_leaves`、`capture_changes`：面板接管期间的通知次数。
- `rendered_left`、`queued_left`：最近输入帧的左键状态及待处理左键事件数。
- `wndproc_message`、`wndproc_phase`、`wndproc_age_ms`：当前窗口消息、所在阶段及阶段持续时间。
- `wndproc_max_ms`：本进程内已完成窗口消息的最长耗时。重入通知返回后恢复外层消息的诊断位置。
- `tracked_mouse_buttons`、`physical_mouse_buttons`：窗口线程维护的按钮位图（含补偿）及最近物理采样位图；位0至4分别为左、右、中、X1、X2。
- `mouse_repairs`、`stale_mouse_messages`：补充的按钮变化次数及跳过的迟到窗口消息数。
- `native_left_down`、`native_left_up`：接受的原生左键事件数；`mouse_x`、`mouse_y`为最近物理采样的客户区坐标。
- `wndproc_outermost`：当前最外层处理函数是否仍为面板函数。其他插件也可能合法包裹并调用本函数，不能只凭false判定接管失效。

阶段编号：0 空闲，1 进入，2 平台任务，3 快捷键，4 显隐，5 拖动范围，6 等待界面锁，7 ImGui 后端，8 消息路由，9 游戏／上游窗口处理函数。持续卡顿时可结合仍在增长的呈现计数区分阻塞位置；日志不记录输入文字，也不等同于线程调用栈或 GPU 性能采集。
