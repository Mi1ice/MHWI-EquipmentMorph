# 0.5.1-dev2：未更新缓冲的重新绑定修复

零权重部位已经绑定并进入原生工作周期，但私有缓冲可能只完成构造初始化，未发生重复上传。旧退役逻辑混用了两类上传标记，导致换装时拒绝退役并停止整个运行时；只更新了部分槽位也会触发。

新逻辑以工作线程记录的最后一次真实上传为依据：仅当期望值仍是构造标记时，允许重复上传字段为空；已经更新的槽必须精确匹配最后记录的上传标记。退役开始、完成检查及复用采用同一规则。资源身份、上传与绘制Fence、后继工作周期汇合和旧句柄失效保护保持有效。

失败时新增 `part_retirement_buffer_rejected`日志，记录部位、槽位、构造/期望/重复上传标记、资源契约和读取结果，日志写入在回调锁之外。

回归直接调用生产 `EndPart`、`DrainStep`及公开API，使用自有内存与假COM Fence。覆盖构造后未更新、部分槽更新、同时退役身体与腰部、来源不释放的反复重绑、新目标零权重、异常更新标记、退役期间更新、上传与绘制完成及后继汇合要求。软件测试不替代真实游戏时序验证。

构建入口为 `tools/check_source.ps1`；候选包为 `.build/packages/MHWI-EquipmentMorph-0.5.1-dev2-source.zip`，尚未实机验收。安装与公共配置来源见[安装说明](INSTALLATION.md)。本轮没有改动帧率相关路径。

实机复测：001身体、腰部绑定后，把身体一个键设为非零并保持接管；直接换其它装备，再切回001。确认出现新目标、权重初始为0、可以重新调节。反复往返，并覆盖腰部始终为0及只调整部分键的情况。日志应出现退役完成和新目标就绪，不应出现全局工作线程失败。
