# 0.5.1-dev3：原生未更新标记的重新绑定修复

历史阶段说明：本页保留对应开发版本的设计、检查数量与当时测试步骤。相关修复已纳入main的dev12基线，本轮用户功能验证与性能优化均已结束；当前状态见[项目状态](PROJECT_STATUS.md)及[dev12结论](DEV12_BASELINE.md)。下文的候选“待复测”不代表当前新增任务。

零权重部位已经绑定并进入原生工作周期，但私有缓冲可能只完成构造初始化，未发生重复上传。旧退役逻辑混用了两类上传标记，导致换装时拒绝退役并停止整个运行时；只更新了部分槽位也会触发。

dev2实机复测显示：零更新部位的重复上传字段为UINT64_MAX，资源契约与读取均成功。只读核对原生构造器确认这个字段的初值正是UINT64_MAX；dev2误用0作为未更新状态，回归夹具也有相同错误，因此未修复真实路径。

dev3以工作线程记录的最后一次真实上传为依据：仅当期望值仍是构造标记时，重复上传字段必须为原生UINT64_MAX未更新值；已经更新的槽必须精确匹配最后记录的有限上传标记。0、未知写入、已更新字段退回未更新状态均拒绝。退役开始、完成检查及复用采用同一规则。

上传/绘制Fence返回UINT64_MAX仍按设备移除拒绝，不能把未更新字段的哨兵值当成完成证明。构造上传必须有有限完成值；资源身份、后继工作周期汇合、绘制完成和旧句柄失效保护保持有效。

失败时新增 `part_retirement_buffer_rejected`日志，记录部位、槽位、构造/期望/重复上传标记、资源契约和读取结果，日志写入在回调锁之外。

回归直接调用生产 `EndPart`、`DrainStep`及公开API，使用自有内存与假COM Fence。修正后的真实初始化用例在dev2上失败，dev3原生共334项通过。覆盖构造后未更新、部分槽更新、同时退役身体与腰部、来源不释放的反复重绑、新目标零权重、异常更新标记、退役期间更新、上传/绘制Fence设备移除及后继汇合要求。软件测试不替代真实游戏时序验证。

构建入口为 `tools/check_source.ps1`；候选包为 `.build/packages/MHWI-EquipmentMorph-0.5.1-dev3-source.zip`，尚未实机验收。安装与公共配置来源见[安装说明](INSTALLATION.md)。正常退出游戏和控制窗口后再更换测试版本，保留已有format=2公共配置。本轮没有改动帧率相关路径。

实机复测：001身体、腰部绑定后，把身体一个键设为非零并保持接管；直接换其它装备，再切回001。确认出现新目标、权重初始为0、可以重新调节。反复往返，并覆盖腰部始终为0及只调整部分键的情况。日志应出现退役完成和新目标就绪，不应出现全局工作线程失败。
