# 并行输入校验 · 0.5.1-dev9

本轮处理非零输入的全局锁排队：Input先在锁内复制玩家选择、owner路由、五个部位的epoch和固定长度配置，再在锁外执行主玩家选择、Renderer与原生输入头的受保护读取。没有adapter、asset或可变配置字符串引用逃出锁，也没有跨回调缓存。活动配置更换与ResetPartLocked的epoch递增在同一锁内完成。

提交时重新核对armed、玩家选择、owner路由及相关部位epoch。仍在锁内新鲜读取owner streams、玩家/桥接/生命周期vtable、部位路由、owner.model、model.source、Renderer计数，并保留私有缓冲Contract、输入替换和覆盖计数。原生周期变化、模型/玩家失效或绑定重置后，旧读取结果不会发布到新代际。无关部位切换不阻断当前输入；玩家选择变化时允许一次重试，持续变化则通过现有自动重绑退役。共享锁升级的试验没有改善合成吞吐，未纳入候选；正式候选仍使用原有mutex。

新增29项回归，带合成profile的完整原生检查共545项。覆盖五个实际计算/绘制/分派回调同时读取、提交区仍互斥、并发玩家移除/模型更换/配置重新分配与重置、旧epoch/选择/路由/arm结果丢弃，以及提交前模型/source/桥接/streams/私有资源/原生计数变化。完整开发入口仍验证作者侧、SDK、控制接口、打包和模拟安装。

自有身体内存直接调用生产Input，读取次数仍为计算/绘制/分派38/39/41；全零仍为0/0/1。配对单线程平均约10.68/10.93/11.48→10.50/10.73/11.24微秒，基本持平。四线程各3000次，按总调用数归一的总墙钟约12.06/12.27/12.92→8.14/8.51/8.35微秒，约降低30%至35%。这是合成吞吐测量，不是游戏内回调延迟、持锁等待分位数或FPS收益；没有真实Hook或GPU调用。

用户确认dev8同场景固定非零平均约170→180 FPS，测试通过且工作正常；本报告不扩展为dev9验收。GPU评估尚未进行。本轮不修改GPU调用、资源退役或实际游戏安装。

开发入口为tools/check_mhwi_equipmentmorph_development.ps1。正常退出游戏和控制窗口后安装dev9，保留已有公共runtime.ini；同场景与dev8对比固定非零帧率，复测连续调节、反向、释放、归零与保持控制的001往返重绑，确认新目标从零开始且可重新调节。
