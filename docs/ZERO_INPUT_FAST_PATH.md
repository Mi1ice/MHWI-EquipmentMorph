# 0.5.1-dev4：稳定零权重输入轻量路径

历史阶段说明：本页保留对应开发版本的设计、检查数量与当时测试步骤。相关修复已纳入main的dev12基线，本轮用户功能验证与性能优化均已结束；当前状态见[项目状态](PROJECT_STATUS.md)及[dev12结论](DEV12_BASELINE.md)。下文的候选“待复测”不代表当前新增任务。

绑定后即使权重为0，原Input仍在每个网格回调中持有全局锁，执行主玩家、渲染器、模型和资源的重复校验。独立CPU测量中，身体Compute零权重路径每次调用78次ReadProcessMemory；非零路径92次。这会把CPU开销和锁等待带到游戏工作线程。

dev4仅优化稳定零权重输入。首个worker的原生Launch确定本周期已经发布原输入，请求和应用权重全为0，三个私有槽均为Free，才启用轻量路由；该决定固定到本周期Signal。计算和绘制回调只保留锁内路由检查，不改任何寄存器；分派回调另读取一次owner帧槽。不访问任意游戏地址的新读取接口，也不使用无保护memcpy替代ReadProcessMemory。

周期中途收到非零请求或上传完成，不会让计算与分派走不同路由；私有输入只能在下一Launch发布并恢复完整校验。非零转零时，活动资源与尚未完成退役的槽保持完整路径，等待原有后继汇合、上传及绘制Fence完成后，下一Launch才启用轻量路径。首次捕获、代际失效、主玩家发现、工作线程与Launch身份检查保持有效。

日志part_state新增original_input_bypasses。稳定零权重时该计数应增长；每个绑定代际重新计数。它是锁内聚合、锁外记录的计数，不逐回调写盘。GPU/Fence设备移除、上传标记等保护不变。

用同一合成夹具对比dev3源码和新实现，单线程零权重Compute路径由约22.414微秒降到0.087微秒；非零路径约26.182和26.430微秒，每次仍为92次读取。夹具直接运行生产Input，仅访问自有内存，不运行真实Hook、驱动或游戏。测量不能换算为实机FPS提升比例。

本轮没有优化每个worker启动时的完整身份检查，也没有调整空闲平滑轮询。相关开销会继续存在。

构建入口为tools/check_source.ps1，包名为MHWI-EquipmentMorph-0.5.1-dev4-source.zip。新包不热替换正在运行的插件；需要正常退出游戏和控制窗口后安装。保留已有format=2公共runtime.ini，来源见[安装说明](INSTALLATION.md)。

在同一场景比较dev3和dev4：装备001，保持身体/腰部所有权重为0，观察帧率及original_input_bypasses；再设置非零、恢复全零，确认视觉、控制和释放正常。保持控制不释放，重复001→其它套装→001，确认新目标从0开始。归零后的轻量路径可能需等待旧资源安全退役。本候选仍需实机复测。
