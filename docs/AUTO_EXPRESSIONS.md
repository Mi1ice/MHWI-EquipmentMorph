# 自动表情配置（开发候选）

本地开发面板的“自动表情”页现可连接独立眨眼插件。正式0.6.0附件不因此改变；
自动表情插件仍是单独验证的组件，不随现有正式安装包提供，也不并入核心。
仅安装核心或核心＋面板时，未加载自动表情插件会显示未就绪，形态键控制仍独立使用。

## 操作

- “启用自动表情”独立控制自动来源，切换后持久保存，不受“启用形态键控制”开关影响。
- 在“眨眼”中选择当前装备及合并双眼闭合的目标形态键，点击“保存映射”。仅列出范围覆盖0～1的键。
  当前只支持一条合并双眼映射，不同时配置左右眼或嘴部。下拉框选择是编辑草稿，保存成功才替换映射。
- “清除映射”释放旧自动贡献并移除关联，独立开关状态保留。
- 关闭面板或切换模块不会停止自动表情；重启游戏恢复已保存的开关和映射，换装后等待同一资源重新绑定。
- 手动及其他高优先来源优先；手动显式零同样覆盖自动值，释放对应控制后自动来源重新生效。
  关闭面板会恢复形态键控制模块已应用的预设，因此预设内的该键仍可能优先于自动来源。

状态显示运行、等待装备、等待角色面部、姿态不一致或不支持；运行时显示原生信号的闭合程度。
该数值不等同于最终绘制权重，高优先来源接管时会单独说明。

## 配置与身份

独立插件在`nativePC/plugins/MHWEquipmentMorph/native-blink.json`保存`schema: 1`配置：
开关、映射是否存在、装备部位、完整资源路径、模型SHA256、形态键包SHA256及目标键名。
相同装备名称或资源路径但MOD／形态键包不同不会自动匹配，需要确认后重新保存映射。
不保存进程内的目标句柄或键索引；重新绑定时按身份和键名重新定位，多个完全相同的候选拒绝任意选择。

配置由独立插件的工作线程校验并原子替换，面板渲染线程不读写文件或调用形态键API。
保存失败保留旧配置和贡献；损坏的启动配置关闭自动输出并提示重新保存。
此开发版本不读取旧`MHWEquipmentMorphNativeBlink.ini`，不迁移旧测试配置。
没有JSON时沿用此前已经验证的测试MOD及`vrc.blink`默认映射；清除映射后保存的空配置不会回退为该默认值。

## 算法与范围

眨眼求值沿用已验证的共同基准，不因面板接入而更改：读取真实面部眼睑局部Y，
消除当前捏脸参数的FCP偏移与区域缩放后归一化，再将左右闭合程度取平均。
固定基准来自原版`pl/common/face_mot/pl_face.lmt`的10／11参考动画，
每份参考以首帧间距为睁眼候选、完整动画的最小间距为闭眼候选；
共同基准每侧采用较小的睁眼间距和较大的闭眼间距。运行时不逐动画切换端点或学习场景极值。

当前原生来源适配女性骨架及已核实的外观修正关系；选择不同目标键不扩大原生来源适配范围。
目标MOD作者应移除面部网格受原生面部骨骼影响的相关权重，以免同一表情重复变形。

## 用户验收

1. 确认默认眨眼继续正常；独立关闭／开启自动表情，关闭面板及关闭形态键控制后分别检查。
2. 选择合适装备和眨眼键，保存后检查；清除映射应停止自动贡献，重新保存可恢复。
3. 保存后重启，检查开关和映射恢复；换装离开再回来时恢复，面板不沿用失效句柄。
4. 手动控制该键（包括零），确认手动优先；释放后恢复自动眨眼。
5. 回归普通待机、画廊过场及返回读档，以及已有预设关闭确认流程。界面和游戏测试由用户执行。
