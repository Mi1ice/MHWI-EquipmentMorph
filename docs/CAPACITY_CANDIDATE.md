# 容量与联合导出候选

此分支的试验范围是每模型1024键、5部位、32来源、单次原子提交5120条和256条事件。C ABI及MHMPACK1／2、MHMPROF1布局不变。profile每源对象允许1024条动态记录加256条非零固定状态，总计1280；128源对象和512KiB总大小保护仍生效。其他包体、偏移、记录和有限数保护保留。1024是软件试验边界，不是游戏性能承诺。

## 已验证组合

- 当前作者联合导出、当前核心、当前SDK：合成65／1024键配对导出以及489／1024键发现、按实际数量读取和末尾键检查；五部位5120条完整提交保持原子性，5121条及非法批次拒绝后旧状态不变。
- 旧小包：保留MHMPACK1／2读取与既有布局回归；提高容量不要求重新打包旧数据。
- 冻结0.4.0旧SDK：核心宣告1024上限时明确返回MHM_CAPACITY，不静默截断。当前SDK目录的0.4.0名称是历史路径，候选身份以源码摘要为准。
- 现有游戏内面板、桌面面板、预设和自动表情／眨眼：本轮未适配或重建，不能混入候选组合。尚有固定64容量的应用视图和客户端，需要独立升级与回归；未运行完整ImGui入口来掩盖这些差异。

宿主使用按实际键数拥有的不可变快照，工作线程捕获仲裁值与修订。保持16毫秒节奏及合并请求，不产生平滑值；需要过渡的应用自行提交过渡权重。保持三缓冲、身份复核、Fence、同权重复用、全零原始输入和安全退役。日志输出完整实际数量数组，保留65536字节行与8MiB轮转保护。

作者GEOMETRIC模式的无定义法线和接近反向端点分别有显式BASELINE规则，默认均为REJECT。规则只跳过对应键的法线变化并记录逐项原因，不改变位置，不放宽非有限值、非法作者法线及其他方向检查；不改变二进制包格式。普通界面不会自动开启规则。

## 验证入口与交付

运行[构建说明](BUILD.md)中的All入口；它必须执行Data、Sdk、Paired、Host四阶段。Data目前含67项作者和127项原生检查；Sdk为4组容量用例和14项原有检查；Paired为255项容量、50项既有导出、62项确认／预览与28项法线规则检查；Host为26项作者夹具与855项原生检查。

报告 `.build/capacity-validation/all-report.json` 保存实际执行结果和摘要。核心DLL位于 `.build/cleanup-validation/native/`，SDK头位于 `sdk/MHWI-EquipmentMorph-0.4.0/include/`，作者源码位于 `blender_addon_v044/`。均为可审阅候选；没有安装到游戏、替换配置或发布。私人真实样本及其测量收据留在维护者外层工作区，不进入产品仓库。

## 后续容量测量提案

待用户确认后，在可比较场景分别测每模型64、128、256、512、1024个注册键；每档明确实际注册部位与五部位合计键数。每档至少分别记录以下负载：

1. 无控制来源，以及保留来源但全部显式零，两者分开采样。
2. 五部位合计30个固定非零键，记录各部位分布。
3. 五部位合计25个固定非零加5个变化键，记录变化曲线及各部位分布。

应记录包体大小、位置／法线记录数、顶点缓冲大小、合成与上传次数、CPU／GPU和帧时间；将同权重复用、归零和换装故障回归分开。更新频率、采样时长、场景与性能预算尚未设定，本计划不自动运行这些实验。软件构建通过不能代替性能预算或视觉验收。

## 尚未关闭的验收

误差只报告测量值，没有新增数值容差。真实模型仍需核对第二套UV删除的材质影响、法线例外的外观和两处基准法线／切线稳定性。作者旧路径收敛、面板容量视图、预设存储与批次边界、眨眼SDK升级、五部位真实样本和实机故障回归属于后续独立工作。C03／C04／C06／C07按各自证据继续验收，不随本候选自动关闭。
