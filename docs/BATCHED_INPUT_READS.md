# 0.5.1-dev7：非零输入的有界批量读取

历史阶段说明：本页保留对应开发版本的设计、检查数量与当时测试步骤。相关修复已纳入main的dev12基线，本轮用户功能验证与性能优化均已结束；当前状态见[项目状态](PROJECT_STATUS.md)及[dev12结论](DEV12_BASELINE.md)。下文的候选“待复测”不代表当前新增任务。

非零回调仍需校验身份并替换输入，稳定权重也会按网格持续执行。原身体夹具中计算/绘制/分派每次分别92/95/82次ReadProcessMemory，全部处于共享gate内。

dev7把同一对象、固定范围内的字段合并为一次受保护读取，再从本地副本提取字段。ReadBlock的长度和字段边界编译期检查，每块最多0x500字节；每次Load仍调用ReadProcessMemory并检查完整读取成功，不直接解引用游戏地址。没有跨回调/周期缓存，没有删除原有身份、资源、映射或诊断条件，也没有取消锁。

Snapshot、SlotMatches和私有缓冲Contract均采用批量字段读取。生命周期vtable、玩家/桥接关联、模型路径/大小/网格数、source模式/引用/资源，以及私有缓冲的视图/映射/初始化标记仍检查。模型和source的末尾身份复核、独立变化的owner streams晚期新鲜读取保持原样；新代际、GPU退役和分派一致性不变。诊断字段本轮仍保留，便于单独比较读取策略的效果。

最终计算/绘制/分派读取为52/53/54次，私有Contract为2次。合成CPU耗时下降不等于实机FPS提升；共享锁仍存在，实际CPU/GPU占比需要同场景采样。

同一自有身体内存夹具的配对测量：单线程计算26.31→18.09微秒、绘制27.34→17.27微秒、分派23.64→16.75微秒；直接调用生产回调，不执行真实Hook、游戏或GPU。原始性能数据不能替代用户实机对比。

新增58项回归，原生共463项：先在dev6复现非零读取预算断言失败，再验证全部契约字段篡改拒绝、构造身份采集、身体/腰部路由、错误网格/分派绑定、读取期间模型替换和owner stream启用，以及不可读页失败关闭。只使用自有内存，不运行游戏或GPU。

用户确认dev6工作正常、调节平滑和换装重绑正常，但稳定非零仍持续掉帧。dev7待独立实机复测：同场景比较全零、稳定非零、归零；调节、反向、释放后保持视觉平滑；保持控制进行001→其它套装→001，确认新目标零值与重新调节。正常退出游戏与控制窗口后安装候选，保留公共runtime.ini。
