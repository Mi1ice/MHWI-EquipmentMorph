# 形态键预设与穿戴默认（开发候选）

需要支持身份查询扩展的核心和可选 Dear ImGui 插件。预设与自动恢复由可选插件的普通后台线程管理，不要求打开窗口；核心继续独立提供形态键 API。用户确认第八阶段功能符合描述；第九阶段增加选择即预览、手动保存和启动／换装自动恢复；2026-10-21 修正为关闭主窗口结束预览并恢复穿戴默认，用户已确认本轮测试通过；正式发行保持不变。第十阶段持久总开关与精简界面已获用户测试确认。第十一阶段将快捷键改为 Del、修正输入法及拖动边界；2026-10-22 用户确认测试通过：中文输入正常，鼠标限制在游戏窗口内后未再出现所报告的卡顿。

## 保存与应用

1. 调节并接管所需部位的形态键。原有复选框继续区分“显式零权重接管”和“释放该键”。
2. 在窗口顶部点击“另存为…”，输入整套预设名称并保存。预设包含本面板已接管的所有部位与键，包括零权重；其他插件的贡献不写入。
3. 主面板“预览预设”列出至少一个部位匹配的预设，支持名称搜索。选中 A 就立即预览 A 中匹配的部位并将 A 设为编辑对象，移除旧的“应用所选”步骤；其他部位的控制保持。管理窗口的条目仍只用于浏览和整理，不会因选择详情而应用。
4. 调节权重只实时改变形变并标记“未保存”，不会自动写入预设文件。“保存当前”将当前编辑对象的修改写入 A；“另存为…”把本面板当前接管的全部部位保存为另一份预设，不自动设为穿戴默认。
5. 不同部位可来自不同自动预设。保存 A 时，只更新归属 A 且当前可编辑的部位，保留 A 中未穿戴部位的原有数据，不把其他预设的控制混入 A。开始编辑另一个装备部位时，该部位归属当前编辑的 A，可在保存时加入 A。

切换预设、关闭形态键控制或关闭主窗口时，如有未保存修改，提供保存后继续、放弃后继续和取消。保存失败不会继续切换，也不会覆盖旧文件；排队处理再次检查编辑对象，避免装备变化后把确认写入另一预设。未命名配置需先另存为，或明确放弃。换装导致目标退役后，该部位未保存的修改不会写入文件，也不会重放到新目标；恢复使用已保存版本，换装前请保存需要保留的编辑。

保存记录已接受的目标权重，保留 float32 精度，避免把平滑中间值或其他优先来源的实际值保存下来。后台先处理保存之前排队的编辑，再保存；若该批编辑被拒绝，则保存失败并显示原因。输入框仍可按回车提交。

核心状态暂时读取失败时保留最后确认的未保存标记，暂停保存；恢复读取后可继续编辑和保存原草稿。此时关闭预览会报告状态未就绪并保持窗口打开，避免未经确认丢弃编辑或在无法核对默认时释放控制。明确选择放弃并关闭形态键控制仍可关闭总开关并释放本面板贡献。

尚无面板贡献时不能保存空预设。勾选并设为零的键仍是有效贡献，可以单独保存。名称最多 128 个 UTF-8 字节，允许中文；同名另存为会提示更换名称。

界面不再常驻显示操作说明和重复状态。“各部位当前配置”直接展开，集中显示当前具有形态键数据的部位、装备名称、完整资源编号、已应用预设，以及不同于已应用配置的临时预览。未保存状态在预设名后用 `*` 标记；普通操作只留一条简短结果，预览选择不重复播报，长错误可展开详情。装备名称从现有目录按完整模型路径查找；共享模型无法唯一确定名称或未知路径时只显示资源编号。完整路径可悬停查看，显示名称不参与兼容性匹配。

关闭主窗口（× 或非文本编辑时的 Del）结束临时预览，按各部位精确匹配恢复用户定义的已保存穿戴默认；没有匹配默认的部位释放本面板贡献。非默认预设 B 即使保存，关闭后仍使用原默认 A，只有“应用预设／取消应用”改变关联。若保存的正是默认 A，则恢复刚保存的版本。关闭确认提供保存并关闭、放弃并关闭、取消；保存或恢复失败时保持窗口打开并报告原因。恢复使用一次完整贡献批量提交，不先释放再逐项套用。总开关关闭时，关闭预览也不会重新开启形变。

## 应用预设与自动恢复

选中并保存所需预设后，点击“应用预设”；管理窗口也能记录关联。此操作只保存关联，不保存未保存的权重，也不打断当前效果。启动游戏完成装备绑定，或重新穿上该模型后，后台按部位恢复关联预设的已保存权重，窗口可始终隐藏。

每个具体部位的模型路径、MOD3 指纹与形态键数据指纹只对应一份穿戴默认。后来设置的预设替换重叠资产的旧关联，非重叠部位保留。例如 A 涉及身体和腰部，B 只涉及同一身体：设置 B 后，身体默认 B、腰部仍默认 A。界面列出每份预设实际关联的部位；不按文件排序、名称或模糊装备名称猜测优先级。

自动恢复响应启动、目标句柄变化、恢复自动使用及意外来源过期，不在每次扫描重复提交；持续调节时不会被已保存值覆盖。只更换腰部不会重置身体的当前编辑。新目标始终重新核对身份与键名，不能把退役句柄或未保存草稿重放到新模型。API 拒绝新的自动组合时保留旧控制并显示原因，不每次扫描重试；修正默认后可明确重试。

“启用形态键控制”是形态键控制模块的开关，首次默认开启。关闭前如有未保存修改，提供保存并关闭形态键控制、放弃并关闭形态键控制和取消；随后保存关闭状态并释放本面板控制，阻止预览、滑块／输入编辑和自动恢复。预设管理及应用关联仍可维护。换装、关闭窗口和游戏重启不会擅自开启；重新开启后恢复各部位已应用的已保存预设，不重放临时草稿。开关仅影响本面板，其他插件的 API 控制保持独立。

开关单独保存在 `nativePC/plugins/MHWEquipmentMorph/panel-settings.json`，只包含格式版本和 `enabled`，不保存窗口布局；首次主动切换时创建。本轮按当前格式处理预设与 `auto-presets.json`，不提供旧测试格式迁移。配置损坏时本面板停止接管、报告错误并保留原文件，用户明确开启后可重写开关配置。写入关闭状态失败时保留原开关和当前控制，保存预设失败时保留编辑；这些错误均不会关闭共享核心 API。“取消应用”移除对应自动关联，保留预设与当前临时预览，关闭窗口后不再恢复被取消的配置。

关联单独保存在 `nativePC/plugins/MHWEquipmentMorph/auto-presets.json`，首次设置时创建；当前预设本体为 `schema: 1`；本轮不保证更早测试文件兼容，也不提供自动迁移。关联按预设编号及部位引用已保存资产身份，最多 256 份预设、每份 5 个部位。重命名不影响关联，删除预设先解除关联，回收区恢复和导入均不自动启用。导出不包含本机默认关联。

自动配置损坏时显示错误并停用此次加载的默认，预设文件保留且不会被自动覆盖。明确修复文件后可重试读取，或在面板重新设置默认。配置写入失败时保留原关联；删除若无法先解除关联，则保留预设。若关联已取消但移动失败，会明确报告两者结果。

## 筛选与管理

点击预设栏的“管理…”，或下拉框内的“管理全部预设”，在主面板右侧打开附随的游戏内管理栏。它随主面板移动、保持顶部对齐和相同高度；拖动右边缘可调整宽度，不能单独移动或改变高度。宽度受游戏画面边界限制，隐藏或关闭后再打开会保留本次会话的宽度，重启游戏恢复默认。靠近屏幕边缘时调整主面板位置，空间不足时缩小布局；特别窄的画面以内侧重叠方式保留可见入口。关闭管理栏后主面板保持当前位置和大小。下拉框没有可用项时，未匹配的预设仍可从此入口找到。

- “全部预设”列出有效预设；“回收区”列出已删除预设。两者均可名称搜索，并按全部、完全匹配、部分匹配、无匹配筛选。英文搜索忽略大小写，中文按原文匹配。
- 选择条目可查看所含部位、匹配结果和逐部位原因；可展开保存的权重及资产指纹。筛选和选择详情不改变当前形态键。
- “重命名”只修改文件中的名称，保留编号、装备身份和权重；当前预设名称同步更新。未保存的面板修改不会被重命名操作写入文件。
- “删除到回收区”将文件移入 `presets/.trash/`，不会释放或改变形态键控制。删除当前使用的预设后，当前配置标为未保存，可另存为新预设。
- “恢复”将文件放回预设列表，但不自动选择或应用。遇到同名预设时，先在回收区中重命名后重试；遇到相同编号的文件时拒绝覆盖。
- 回收区条目的“永久删除”会先显示名称和不可撤销提示，确认后仅删除该回收文件。“删除全部”同样需要确认，范围是整个回收区，包括被当前搜索或匹配筛选隐藏的预设；取消不执行删除。两者均不释放或提交形态键权重。

管理不要求当前穿戴匹配装备，也不要求核心已连接。主面板快捷键及“×”结束预览并恢复穿戴默认，成功后隐藏主面板和管理栏；关闭管理栏本身不结束预览。失焦或最小化仅暂时隐藏并保留编辑，不弹出关闭确认。每次启动使用默认位置、尺寸和默认管理栏宽度，运行中仍可拖动调宽，不保存布局偏好。

回收区会在重启后保留。永久删除无法从面板恢复；文件不可写时保留文件并显示错误。批量删除逐项执行，部分失败时显示成功与失败数量，只移除成功项，可检查权限后重试。仅处理回收区根目录中编号合法的 `.json` 文件，也包括这类文件中损坏而未能显示的预设；非预设文件、链接和子目录不会被递归删除。文件移动失败、重命名保存失败或恢复冲突时保留原文件。只处理经过校验的预设编号，不接受显示名称作为文件路径。

## 导入与导出

继续使用 `schema: 1` JSON，一份文件保存一套预设。仅携带名称、编号、部位、资产指纹、形态键 ID 和权重，不含 MOD、贴图或运行时句柄。导入不转换 MOD 身份，应用仍需严格匹配。

导出：在“全部预设”中选择条目点击“导出”，或点击上方“导出全部”。导出全部包含正常列表的全部预设，不受搜索／匹配筛选影响，也不包含回收区。导出的是已保存内容；当前调节未保存时先保存或另存为。

每次导出在 `nativePC/plugins/MHWEquipmentMorph/exports/` 中创建带时间与独立编号的子目录，文件以预设编号命名，名称仍保存在 JSON 内。完成后显示目录、成功和失败数量；不覆盖以前的导出。批量逐项写入，失败时保留已成功导出的文件，显示错误原因。需要分享或备份时复制对应文件夹或其中的 JSON 即可，首版不处理 ZIP。

导入：

1. 将收到的 JSON 放入 `nativePC/plugins/MHWEquipmentMorph/imports/` 根目录。
2. 在“全部预设”点击“导入…”，面板在游戏内刷新预览；后续增删或修改文件后点击“刷新预览”。首次刷新会创建目录。
3. 勾选待导入项目，点击条目可查看文件名、部位／键数量和当前装备匹配情况，并编辑导入名称。可全选有效项或取消全选；无效文件列出原因且不能勾选。
4. 点击“导入勾选项”，查看新增、重复跳过和失败数量。无需重启；完成后不自动选择或应用，不改变当前控制和未保存状态。

预览只扫描根目录中的 `.json` 文件（扩展名忽略大小写），支持 UTF-8 和 UTF-8 BOM，不跟随链接或递归扫描文件夹。一次最多 256 个 JSON，单文件最多 256 KiB。预览已读取并校验文件，确认时使用该预览内容；源文件随后变化不会悄悄改变导入结果，需要刷新才能更新。

同名且内容相同的预设跳过；忽略内部编号及部位／键的排列顺序。名称相同而内容不同，默认建议“原名（导入）”或带序号的名称，允许修改，确认时再次检查。格式损坏、版本不支持、名称或权重无效、预览失效、库容量不足等会拒绝对应条目，其他有效条目继续导入；部分成功不会回滚成功项。源文件保持原样。

每份新导入预设生成新的本地编号并以不覆盖方式写入，不覆盖正常列表、回收区或相同编号的既有文件。当前装备不匹配或核心未连接仍可导入／导出；不匹配项在管理列表保留，正常预设下拉框继续只显示可应用项。

## 严格匹配

每个保存的部位同时核对：部位、模型资源路径、MOD3 的 SHA-256、形态键数据包的 SHA-256、形态键 ID 和权重范围。指纹来自核心启动时已校验并加载的资产，面板不在拖动或绘制时读取 MOD 文件。

- 同名装备替换了 MOD3，或同名形态键的数据包内容改变：不兼容。
- 未穿戴或尚未绑定的部位等待后续绑定；缺少键、权重不符合核心范围或无法确认身份的部位不应用。
- 预设未涉及的其他穿戴部位：不影响匹配。
- 仅更换贴图，模型和形态键数据包未变：仍可匹配。
- 换装后出现相同内容的新目标：重新匹配，有已应用预设且开关开启时自动恢复其已保存权重。

按部位校验后，构造保留无关部位的完整贡献集合，用一次 API 批量提交。被选中预设替换的部位中，旧集合未包含在新预设中的键释放；未涉及的部位保持。批量被拒绝时不部分应用。各部位实际网格仍沿现有独立发布和平滑流程更新，不承诺同一个 GPU 帧同时切换。原有严格整套批量路径继续作为底层回归验证保留，主面板采用新的按部位选择路径，公开核心 API 不变。

## 文件与错误处理

文件位于游戏目录下 `nativePC/plugins/MHWEquipmentMorph/presets/`。保存成功时创建目录，每份预设为一个 JSON 文件，文件名使用独立编号，不使用显示名称作为路径。

JSON 格式版本为 `schema: 1`，含编号、名称及逐部位的身份、形态键 ID、权重。不保存运行时句柄和键索引，不包含模型或贴图。加载时重新解析当次有效目标；校验后发生换装时，核心会拒绝失效句柄。

文件读写在普通后台线程执行。写入临时文件并完成刷新后替换正式文件；保存失败保留旧文件。正常列表最多 256 份、回收区最多 1024 份，单文件不超过 256 KiB。损坏文件单独跳过并显示数量，重复字段、非法数值和不支持的版本会被拒绝。

正常预设库与回收区分别加载、分别报告错误；回收区目录读取失败不会隐藏正常预设或阻断其自动应用，也不会重写预设及关联文件。批量文件操作中发现控制租期失效时，通知统一恢复流程，清除已失效临时编辑并拒绝同批次后续旧编辑；开关开启且自动使用未暂停时，重新按当前装备匹配已保存默认。文件操作的成功或失败独立报告。

首次启动和文件管理操作维护内存列表；匹配结果按目标身份与预设变更缓存，拖动滑块不重新匹配整个库或回收区。管理与导入列表仅绘制可见条目，不在绘制或权重读回时扫描磁盘。批量删除、导入／导出期间在文件操作间按约 500ms 为现有控制来源续租。外部手动修改正式预设库后重启游戏以刷新；导入暂存文件由“刷新预览”重新读取。文件读写支持 Windows 长路径。跨不同 MOD 转换预设仍未实现。

## 可选身份查询扩展

公开头文件为 [mhw_morph_identity.h](../runtime/EquipmentMorphPerKeyCore/include/mhw_morph_identity.h)，SDK 内提供相同副本。通过动态查询导出 `MhwMorphGetAssetIdentity` 调用，传入扩展版本、输出结构大小和当前目标句柄。

原 `MhmApi` v1 布局、版本和 getter 保持兼容。未提供扩展的旧核心仍可使用普通面板控制，预设功能显示需要配套核心。未携带已验证摘要的旧式宿主目标返回 `MHM_NOT_READY`，已退役目标返回 `MHM_STALE`；失败不修改输出。扩展不接受客户端提供的摘要来替代核心已加载资产。

## 非界面验证

先运行 `tools/build_mhwi_equipmentmorph_current.ps1` 构建核心，再运行：

```powershell
./tools/build_mhwi_equipmentmorph_imgui.ps1 -CoreCandidate .build/cleanup-validation/native/MHWEquipmentMorphConfiguredPrototype.dll
```

构建只运行控制和预设的控制台回归；`-CoreCandidate` 另行核对实际 DLL 的旧 API 和身份扩展导出。它不会启动图形窗口或游戏。界面、手感及实机测试由用户执行。
