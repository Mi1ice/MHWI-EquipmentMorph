# 0.5.1-dev6：空闲平滑与采样节奏

历史阶段说明：本页保留对应开发版本的设计、检查数量与当时测试步骤。相关修复已纳入main的dev12基线，本轮用户功能验证与性能优化均已结束；当前状态见[项目状态](PROJECT_STATUS.md)及[dev12结论](DEV12_BASELINE.md)。下文的候选“待复测”不代表当前新增任务。

原PartStep在每次轮询都重建目标权重并调用SetTargets，即使公开请求修订没有变化，仍分配映射节点、复制平滑状态。稳定样本未产生新帧时，采样时钟也没有前移，后续循环会持续采样，超过原定16毫秒间隔。

dev6保留每轮公开权重读取，只在请求修订变化时更新平滑目标。修订覆盖提交、释放、来源过期和目标变化；新绑定代际清空修订缓存。读取的输出向量按部位复用，临时权重状态改用最多64键的固定栈缓冲。平滑公式与参数保持原样。

成功提交及未变化样本都推进采样时钟。上传不可用、捕获时修订过期或主机帧容量不足时，时钟保持到期，下轮继续重试。采样目标仍是16毫秒；初始化捕获、换装、身份校验、GPU完成查询、帧确认与回收，以及1/5毫秒工作线程轮询保持原样。未优化非零Input的逐网格检查。

新增23项回归，原生共405项通过。真实PartStep合成回归覆盖空闲节奏、同值新修订、来源释放、过期/容量重试、等待上传、换装失效和代际重置；请求读取覆盖64键上限、容量复用及旧目标失效。64键解析平滑在启动、反向和释放过程，与旧逐轮刷新路径的采样差异不超过1e-6，最终归零。

单身体单键、自有内存夹具直接调用生产PartStep并模拟原生周期状态。每轮5毫秒时堆分配从13次降到3次，1毫秒时平均2.25次；仍保留每轮48次身份读取。5毫秒夹具单轮CPU耗时约13.244→12.876微秒，仅小幅下降。该测量不含真实Hook、游戏或GPU，不能承诺明显帧率提升。

用户确认dev5工作正常、换装重绑正常，帧率改善不明显。dev6需独立实机复测：保持相同场景和视角，比较全零、持续非零与归零帧率，观察调整/反向/释放是否顺滑，再保持控制不释放进行001→其它套装→001往返，确认新目标零值及重新调节正常。

测试包为MHWI-EquipmentMorph-0.5.1-dev6-source.zip。正常退出游戏和控制窗口后安装，保留现有公共runtime.ini。原正式发行保持原样。
