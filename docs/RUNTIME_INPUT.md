# 0.5.1-dev8：运行时输入校验与诊断分离

历史阶段说明：本页保留对应开发版本的设计、检查数量与当时测试步骤。相关修复已纳入main的dev12基线，本轮用户功能验证与性能优化均已结束；当前状态见[项目状态](PROJECT_STATUS.md)及[dev12结论](DEV12_BASELINE.md)。下文的候选“待复测”不代表当前新增任务。

dev7合并了内存读取，但运行时仍先执行完整观察器Snapshot，再重复验证许多相同字段。dev8用ReadInputFacts在同一个回调内完成一次运行时校验。完整observer::Snapshot仍供诊断采样使用，不再位于生产输入替换路径。

运行时保留主玩家选择、前后两次玩家/桥接/vtable证明、部位路由、模型路径/大小/网格范围、原始source模式/引用/资源、实际绑定输入头、晚期owner streams、末尾model/source身份复核和渲染计数。绑定context本身及网格仍检查可读。私有缓冲完整Contract、GPU退役及Compute/Dispatch一致性不变。

运行时不再采集QPC、线程ID、LOD、drawStreams、上下文诊断标志或遍历诊断子对象。仅诊断子对象不可读时，不再因此拒绝运行时输入；完整诊断仍会拒绝并保留原始行为。没有跨回调或原生周期缓存，没有改变共享gate或GPU调用。

已绑定目标会与刚验证的owner/model/source/player身份比较；有效新模型或新source也必须让旧代际失效。首次捕获仅接受验证通过的原输入，不提前发布资源。失败路径仍使用完整Matches诊断身份变化并触发既有重绑/停用流程。

新增53项回归，原生共516项通过：完整字段拒绝、身体/腰部三路径、诊断分离、不可读context/mesh、读取期间model/bridge/streams变更、错误私有槽、映射缓冲拒绝、有效新模型/source使旧代际失效，以及首次捕获。零值轻量路径与已有退役/重绑回归保留。

同一自有身体夹具中，非零计算/绘制/分派每次读取52/53/54→38/39/41，配对CPU耗时约14.68→10.48、14.95→10.70、15.24→11.27微秒。基准直接调用生产回调，不运行真实Hook、游戏或GPU；测试时CPU状态不同会改变绝对时间，不能换算为FPS收益。
